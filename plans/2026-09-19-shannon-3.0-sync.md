# Shannon 3.0 Sync Plan — shannon-on-claude-code

Date: 2026-09-19. Upstream: KeygraphHQ/shannon @ main (pushed 2026-09-08, Shannon 3.0 live).
Local: 5-phase native pipeline, 13 agents, 5 vuln classes, md-only report, no resume.

## Goal

Port upstream Shannon 3.0's load-bearing improvements into the Claude Code native
repo WITHOUT Temporal, Docker, or worker processes. Minimal, clean, symmetric.

## Upstream deltas that matter (verified via gh api + raw.githubusercontent)

1. **6th category: miscellaneous** — `exploit-miscellaneous.txt`,
   `task-formation-miscellaneous.txt`, `sast-enrichment-miscellaneous.txt` exist.
   No `vuln-miscellaneous.txt`: misc queue comes from SAST/reconciliation path
   (`miscellaneous_exploitation_queue.json`, stable `MISC-NN` IDs). Generalist
   exploiter: session lifetime, error disclosure, sensitive logging, cleartext
   storage, CSRF, open redirect, clickjacking, races.
2. **Task-formation stage** — dedupe/grouping between analysis and exploitation.
   Input: opaque-labeled queued findings. Rule: group only when one proof plus one
   verdict settles all members; prefer split over merge. Output: groups array.
3. **SAST enrichment** — converts raw SAST JSON into exploitation-queue shape
   (`ID, vulnerability_type, externally_exploitable, confidence, notes` plus
   `_sastId` join key).
4. **validate-authentication** — preflight credential check with Playwright,
   form/SSO/TOTP, `success_condition`, `state-save` so downstream agents restore
   session instead of re-logging in.
5. **Capella 10-stage SAST** — `architecture, threat_model, plan, triage,
   research, review, confirm, critic, dedupe, calibrate` (Mantis-derived).
6. **Reporting** — md + pdf + SARIF 2.1.0 (default on for exploit runs) + JSON.
   Severity map: critical/high error, medium warning, else note. Rules tagged
   OWASP Top 10 2025. `report.sarif: false` opts out.
7. **Config schema** (8 top keys) — `description, authentication, rules,
   agentic_sast, exploit, report, rules_of_engagement, login(deprecated)`.
   Auth: form/sso/api/basic, TOTP, email-OTP, login_flow placeholders
   ($username/$password/$totp...), success_condition (4 types). Rules:
   avoid/focus, 7 types incl. `code_path` globs. Report: min_severity,
   min_confidence, guidance, sarif flag.
8. **Workspaces + resume** — per-run workspace, per-agent checkpoint, resume by
   re-running identical start with same `-w` name; URL mismatch rejected.
9. **AI providers (BYOK)** — one model per scan (`provider:model-id`),
   Anthropic/OpenAI/xAI/Bedrock + any Pi catalogue provider, custom base URL
   (endpoint override, dialect must match), `--models-config` for new models,
   local via Ollama/vLLM/LM Studio.

## Design decisions (one each, no menus)

Response to review (2 reviewers, both REQUEST-CHANGES, 2026-09-19):
- Misc reframed as NATIVE-ONLY extension (upstream misc is SAST/reconciliation
  internal: exploit/task-formation/sast-enrichment-miscellaneous exist, no
  vuln-miscellaneous analysis file; upstream docs still say 5 fixed classes).
  Native adds vuln-misc because native has no SAST SARIF feed. SARIF rule name
  `shannon/miscellaneous` matches upstream convention.
- Verified by direct Read: `native/mcp-stdio-wrapper.mjs` has NO misc types
  (16 DELIVERABLE_TYPES keys, 5 classes). Reviewer claim of existing
  MiscellaneousVulnerability was hallucination; rejected.
- Shared partials cut 4 to 3 (dropped rules-of-engagement; SKILL covers it).
- Docs cut 4 to 3 (providers folded into configuration.md).
- Resume hardened with scan_meta.json URL binding + validate-before-skip.
- SAST-lite runs in white-box mode only (cost control).
- Frontmatter fully specified below. No SHANNON_MODEL env (frontmatter pinned).

1. **Misc: symmetric 6x6.** Upstream misc is analysis-less because SAST feeds its
   queue. Native has no SAST SARIF pipeline, so add `vuln-misc.md` (generalist
   analysis producing `miscellaneous_exploitation_queue.json`) PLUS
   `exploit-misc.md`. Keeps pipeline symmetric, no special-casing in SKILL.
2. **Reconcile: one agent, not two stages.** Upstream task-formation plus
   reconciliation plus SAST-enrichment collapse into a single native `reconcile`
   agent (runs after vuln analysis, before exploitation). It merges 6 queues
   plus SAST findings, dedupes (split-over-merge rule), outputs
   `reconciled_exploitation_queue.json`. Exploit agents read reconciled queue,
   fall back to per-class queue.
3. **SAST: Capella-lite, one agent.** Full 10-stage Temporal workflow is out of
   scope for native. New `sast` agent does architecture plus threat-model plus
   triage sweep, outputs `sast_deliverable.md` plus `sast_findings.json`
   (queue-shaped, with `_sastId`). Runs as Phase 1b in parallel with recon.
4. **Validate-auth: gate agent.** New `validate-auth` agent runs as Phase 0b
   (after scope confirmation, before Phase 1) ONLY
   when login instructions present. Saves `auth_validation.json` (target_url,
   login_success, session_note). Agents re-login with the same flow by default.
5. **Shared partials: 3 files, new agents only.** Add
   `.claude/shared/{severity-reasoning,reporting-standards,exploit-scope}.md`
   ported from upstream partials (+ `credentials-hygiene.md` added in review). Reference from new agents plus report. Do NOT
   rewrite all 13 existing agents in this sync (scope creep); they keep the
   PLACEHOLDER convention which is compatible.
6. **SARIF/JSON: wrapper types plus report agent.** Extend
   `native/mcp-stdio-wrapper.mjs` with MISC_*, SAST_*, RECONCILED_QUEUE, SARIF,
   JSON_REPORT types plus Misc Zod schema. Report agent writes md plus json
   plus sarif (SARIF 2.1.0, rule-per-class, OWASP tags, level map). No PDF
   (needs typst toolchain; document as upstream-only).
7. **Config: example file plus SKILL flag.** Add `shannon-config.example.yaml`
   (auth, rules, exploit, report fields mirroring upstream schema subset).
   SKILL Step 2 accepts `--config <file>`; interactive questions remain default.
8. **Resume: existence checks plus --fresh.** SKILL per-phase: skip phase when
   its deliverable already exists, unless `--fresh` passed. Document workspace
   binding via `scan_meta.json` canonical target URL + `--fresh` (documented in docs/configuration.md).
   No hidden checkpoint dirs (keep native simple: deliverables ARE checkpoints).
9. **Models: keep assignments.** Keep opus/sonnet/haiku frontmatter pinned; no env override (plan review rejected SHANNON_MODEL).
10. **Docs: 3 short native docs.** `docs/{configuration,safety,
    coverage-roadmap}.md`, native-adapted (no Docker,
    no Temporal, Claude Code paths). Providers folded into configuration.md.

## New pipeline (7 phases)

```
Phase 1:  Pre-Recon (code review / black-box ext recon) -> pre_recon_deliverable.md
Phase 1b: SAST-lite (NEW, parallel with Phase 2)        -> sast_deliverable.md + sast_findings.json
Phase 2:  Recon (attack surface)                        -> recon_deliverable.md
Phase 0b: Validate-auth (NEW, login scans only, runs before Phase 1) -> auth_validation.json
Phase 3:  Vuln x6 parallel                              -> *_analysis + *_queue
Phase 3b: Reconcile (NEW)                               -> reconciled_exploitation_queue.json
Phase 4:  Exploit x6 parallel (conditional)             -> *_evidence
Phase 5:  Report (md + json + sarif)                    -> comprehensive_* {.md,.json,.sarif}
```
